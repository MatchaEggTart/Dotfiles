# MISSION.md 格式

`MISSION.md` 放在工作区根目录。它记录**为什么**学这个东西。所有教学决策都要能追溯回它。

## 模板

```md
# Mission: {主题}

## 为什么
{一到三句。具体的、现实世界里的目标。学会之后，他们的生活或工作会变成什么样？
不要写成「理解 X」这种抽象话，逼出背后的结果。}

## 成功长什么样
- {一件具体的、能观察到的事}
- {另一件具体的}
- {…}

## 约束
- {时间、预算、已有承诺、学习偏好，任何限制做法的东西}

## 不碰
- {用户明确不想碰的相邻话题。保护最近发展区}
```

## 规则

- **一个工作区一份 mission。** 两个不相关的主题就是两个工作区。
- **具体优于抽象。** 「十月跑完半马」胜过「变得更健康」；「给团队交付一个 Rust CLI」胜过「学 Rust」。
- **对含糊零容忍。** 如果用户说不清为什么，先访谈再落盘。一份烂 mission 比没有更糟。
- **现实变了就改。** mission 会变。用户的目标移动了就更新它，别让一份过期的 mission
  在背后继续指挥后面的课。改之前先跟用户确认。
- **保持短。** 超过一屏，它就不再是罗盘，而是一份计划了。
